# 会話の要点メモ

会話が消える前に、「何を頼まれ、どこまで進んだか」を一時フォルダのメモに残し、次の会話には**メモの場所を一行だけ**伝える。モデルは呼ばないので、費用は 0。

← [README](../README.md)

## いつ書くか

| いつ | 書くか | 次の会話に渡るもの |
|---|---|---|
| `/clear` の直前 | **書く**（設定 `handoffNote`、既定オン） | メモの場所の一行 |
| 要約（`/compact`・自動要約）の直前 | **書く**（同じ `handoffNote`） | 要約の最後に `Details: <メモの場所>` の一行を付けるよう頼む。要約のあとに始まる会話にも、場所を一行だけ渡す（「要約が主な記録で、足りない詳細があるときだけ読むこと」）。要約を書くモデルが `Details:` を落としても届く |
| `/tokenomics handoff` を打ったとき | 書く（`handoffNote` がオフでも、効果を測る側でも） | なし。続きの会話で、そのメモを読ませる |

- **`/clear` のあとの一行:** 「前の会話のメモはここにある。前の続きを頼まれたときだけ読むこと」という一行だけが渡る。**メモの全文は渡さない。** 別件で `/clear` したときに、読み直しの節約を損なわず、前の作業へ引き戻さないため。
- 効果を測る側の人（`holdoutPercent`）には、`handoffNote` による既定のメモも一行も出さない（`/tokenomics handoff` と、提案の「要約する」を自分で受け入れたときの要約前のメモは別）。
- 内容のある会話で `/clear` したときだけ出る。空の会話で続けて `/clear` すると、メモも一行も出ない。

## 中身

ルールで抜き出す（モデルを呼ばない）。要約ではなく、事実の控え。

- 前の要約の先頭（あれば。1,500 字まで）
- 依頼: 直近 8 件。依頼が 9 件以上のときは、最初の依頼を別枠で（各 400 字、最初の依頼は 600 字まで）
- 最後の回答（2,500 字まで）
- 編集したファイル、読んだファイル（各 40 件まで）
- 実行したコマンド（新しい 20 件まで。`ls`・`grep`・`sed -n`・`git status` のような**見るだけのコマンドは除き**、失敗したものには印を付ける）
- 一時フォルダに置いた作業ファイル（新しい 10 件）
- **git の状態**（`git status --short --branch`。40 行まで、1 行 160 字まで。リポジトリの外なら、この節ごと出ない）

本文は約 12,000 字で、足りなければ後ろ（読んだファイルなど）から切る。git の状態は別枠で、最大約 6,500 字足される。`/clear` では、終了処理の時間制限が短いので、git の状態は一行を渡す直前にメモへ書き足す（制限は 2 秒と残り時間 − 0.3 秒の小さいほう。0.3 秒未満しかなければ付けない）。

## 置き場

一時フォルダの `claude-tokenomics/<セッション>/` に、次の名前で置く。

| ファイル | いつの |
|---|---|
| `handoff-<連番>.md` | 要約のメモ |
| `handoff-pre.md` | 要約の「precompute」（まだ入れ替えない下書き）。件数の記録には載らない |
| `handoff-<13 桁の数字>.md` | `/clear` と `/tokenomics handoff` のメモ（作った時刻） |

- `<セッション>` はエンジンのセッション ID で、**`/clear` では変わらない**。同じプロセスの中のメモと[縮めた出力の全文](savings.md#大きなコマンド出力を縮める)は、会話が替わっても同じフォルダに入る。場所は、次の会話に渡る一行の絶対パスで探す。
- 本人だけが読める場所（`TMPDIR`）がない環境では作らない。消す仕組みはない。
- **モデルがこのメモを読むときは、許可を聞かない**（縮めた出力の設定に関係なく）。許可するのは `Read` ツールだけで、現在のセッションのフォルダの `handoff-*.md` に限る。`cat` など Bash で読むときは、通常どおり確認が出る。

## 台帳に残るもの

件数だけ。内容は入らない。

- `/clear`: `clear_note_written`（書いた）・`clear_note_skipped_*`（空・読めない・時間切れ・一時フォルダなし・効果を測る側）・`clear_note_failed`・`clear_pointer_given`（一行を渡した）・`clear_start_without_note`（`/clear` のあとの開始に、メモが届いていない）
- 要約: `compact_note_written`・`compact_pointer_given`・`compact_start_without_note`
- `/tokenomics handoff`: `fresh_note_written`
- **メモが開かれた回数:** モデルが **Read ツール**または **`cat`・`head`・`tail`・`less`・`more`・`nl`・`bat`・`sed -n`**（`-i` なし）で書いたメモを開くと、`note_read_compaction`・`note_read_clear`・`note_read_fresh` が増える。1 つのメモは**最初の 1 回だけ**数える。書かれてから何ターン後かは合計 `noteTurns` に入る（0 は同じ返信の中）。
  - 数えないもの: サブエージェントが開いたもの、許可されなかった・失敗した呼び出し、メモの名前を文字で書いただけの操作（`ls`、ほかのファイルへの書き込み、`sed -i`）、python などで読んだもの。
  - プラグインを再読み込みしたあとは、書いた覚えのないメモを、このプラグインの一時フォルダにあるときだけ `note_read_other` として数える。
  - **メモの場所もファイル名も台帳には入らない。**
  - 開かれた割合は、要約と `/clear` では「一行で知らせた回数」に対する割合として `scripts/ledger-report.sh` の【要約・/clear のあとに残すメモ】に出る。`/tokenomics handoff` のメモは件数だけ。

### 件数の読み方

`/tokenomics export` の JSON の `days[].counts` に並ぶ。

- `clear_start_without_note` が多い: `/clear` のあとの開始にメモが届いていない。原因は `clear_note_skipped_*` の内訳（空の会話、一時フォルダなし、効果を測る側、時間切れ、読めない）と `clear_note_failed` で見る。`clear_note_written` が 0 なら、`/clear` の直前に会話が読めていないかもしれない。
- `clear_note_written` があるのに `clear_pointer_given` が 0: 一行を渡す側が働いていない。
- 時間切れ（`clear_note_skipped_budget`）: `/clear` の終了処理の残り時間が 0.7 秒未満のとき、メモを作らない。非常に長い会話（数十 MB の記録）で起きうる。エンジンの時間制限（約 1.5 秒。設計書による）で途中で打ち切られた分が、どの件数に入るかは確かめていない。

## 実機で確かめる手順

1. プラグインを読み込み直す（`/reload-plugins`）。
2. 少し作業してから `/clear`。内容のある会話で試すこと。
3. 新しい会話で「前の会話のメモの場所は分かりますか？」と聞く。一行が届いていれば、モデルがメモのパスを答える。
4. 答えのパスのファイルが実際にある。

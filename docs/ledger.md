# 台帳（効いたかどうかを測る）

節約が効いたかを後から確かめるために、**件数と合計だけ**を端末に残す記録。パイロットで集めて数える。

← [README](../README.md)

## 何が入るか

- **日ごとの件数と合計**（1 日 300 キーまで。超えた分は `other` にまとめる）と、**直近の事象 200 件**。
- 保存先は、プラグインの保存場所（`~/.claude/plugins/store/` の下）。**64KB 以内、14 日分。** 64KB を超えると、古い事象、次に古い日の順に捨てるので、14 日に満たないことがある。
- 入っているのは、事象の種類・施策の名前・トークン数・見込み額・やりすぎの指標だけ。
- 見込み額は**入力側の価格だけ**で計算した概算（出力の単価は入れていない）。

## 何が入らないか

プロンプト、ファイルの名前やパス、コマンド、生のセッション ID は入らない。

- 言葉は、英数字と `_ . : -` だけの短い語（タグは 40 字まで）しか受け付けない。空白や `/` を含むパスや文は弾く。ほかの値は数。
- 直近の事象には、セッション ID の 8 桁のハッシュと時刻が入る。書き出し（下）には入らない。
- サブエージェントの種類は、エンジンとこのプラグインが付けた名前（`Explore` など）だけ。自分で定義したエージェントは `custom`、ほかのプラグインのものは `plugin` と記録する（名前にプロジェクト名が入りうるため）。
- メモの場所もファイル名も入らない。

## 見る・渡す・消す

| コマンド | 意味 |
|---|---|
| `/tokenomics` | 分析ペインの「今日の節約」に、今日の分が出る |
| `/tokenomics good` / `bad` | 任意の評価を 1 件だけ残す（作業の内容は残らない） |
| `/tokenomics export` | 件数と合計を JSON でクリップボードにコピーする。パイロットで送る用。一時フォルダがあれば `ledger-export.json` にも書く。画面に出すのは「コピーした」ことだけ（コマンドの出力は会話に入って、以降のターンで読み直されるため）。クリップボードも保存先もないときだけ、記録を画面に出す |
| `/tokenomics reset-ledger` | この端末の台帳を空にする |

書き出しの JSON には、件数と合計のほかに、設定の値・treat か control かの別・匿名の参加者名（人ごとのハッシュ）・Mod の版が付く。直近の事象は含まない。

集計は `scripts/ledger-report.sh export-*.json`（`jq` が要る）。確定と推定は別の節に分けたまま足さず、効果を測る側（control）と節約する側（treat）を並べて、1 ターンのプロンプトの平均・冷えた戻り・任せた回数を比べる。人数が少ないうちは目安で、別の人どうしの比較。同じ人の書き出しが 2 つのファイルにあると、二重に数えずに拒む。パイロットの進め方は `docs/design/pilot-plan.md`。

## 何を数えているか

### 効果を測る側（`holdoutPercent`）

効果を測るため、この割合の人には節約を一切せず、記録だけにする（通常 0）。人ごとに決まる。この人たちは、digest・steer・delegation が `observe` に落ち、軽いエージェントも隠れ、一文も足されず、帯の節約は「0 tok」になる。

### メインの会話の外で使われたトークン

- **サブエージェント:** どの種類でも、`delegation` に関わらず、1 回の実行ごとに `sub_<モデルの種類>`（`sub_haiku` など）を 1 件数え、トークンを `subIn_`・`subWrite_`・`subRead_`・`subOut_`（入力・キャッシュ書き込み・キャッシュ読み・出力。**API が返した数字**）に分けて足す。モデルの種類を名前に入れるのは、値段の違う種類を足すと意味がなくなるため。メインの会話のターン・リクエスト数・グラフ・帯には入れない。
- **アドバイザー:** 呼び出し 1 回ごとに `advisor`（サブエージェントの中は `advisor_sub`）を 1 件数え、**推定の入力** `advIn` と**待ち時間** `advMs`（ミリ秒）を足す。API はアドバイザー自身のトークンを渡さないので、`advIn` は「その回の要求の入力 ÷（呼び出し数 + 1）」で見積もる。この PC の 33 回の実測（記録のアドバイザー自身の数字との比較）では、実際の入力は見積もりの基にした要求の入力の 1.00 倍（0.89〜1.01 倍）で、毎回キャッシュなし。**出力は見えず**（実測は 1 回 約 5〜10k tok）、台帳には入らない。
- どちらも `scripts/ledger-report.sh` に別の節で出る。**確定（サブエージェント）と推定（アドバイザー）は足さず、メインの会話の数字にも足さない。**「リクエスト」として数えるかどうかは決めていない（数えていない）。

### リクエストの形（`request_shape`）

返信ごとに 1 件。**メインの会話のリクエストが何回あったか**（`shpReqs`）、そのうちツールを頼んだもの（`shpTools`）、読み取りを**1 回でまとめて頼んだもの**（`shpParallel`）、**読み取り 1 つだけのリクエストの直後が、また読み取りだったもの**（`shpSerial`。その直後のリクエストが読んだ会話の大きさを `shpSerialTok` に足す。うち同じファイルを続けて読んだ数が `shpSameFile`）、頼んだ呼び出しの総数（`shpCalls`）を数える。

- リクエストは 1 回ごとに会話を丸ごと読み直すので、「1 回で済んだかもしれない読み取り」の読み直しがどれだけあるかを見る記録。**何かを変えるものではない。**
- **これは上限であって、減らせた量ではない。** 2 つ目の読み取りが 1 つ目の結果に頼っていたか（読んだ中身で次に読むファイルを決める、など）はプラグインに見えない。頼っていたものは、まとめて頼めない。「読み取り」は、エンジンが各呼び出しの結果に付ける読み取り専用の印で数える。サブエージェントの分は入れない。ファイル名・コマンドは記録しない（同じファイルかどうかは、その場でだけ比べる）。
- **スキルへの誘導が止めた呼び出し**も同じ記録に残す（`shpRefused`。その次のリクエストが読んだ会話の大きさが `shpRefusedTok`）。止めるたびにモデルは止めた旨を読んでもう一度応答するので、リクエストがおよそ 1 つ増える。減らす側の記録と、増やす側の記録を並べて見るためのもの。
- 実機（2026-10-13）で確かめたこと: 3 つの読み取りを 1 回で頼ませると `shpParallel` が 1、1 つずつ頼ませると `shpSerial` が 2、止められた検索は `shpRefused` が 1 になる。エンジンはツールの呼び出しを、リクエストの応答が揃う前に始めることがあるので、各リクエストの形は**始まるときに開いて**呼び出しを数えている。

### 読み取りをまとめて頼む一文（`B7`）

`fired`（足したセッション）・`signal session_off`（足さなかったセッション）・`would`（足すはずだったセッション）の数と、各側の返信ごとの合計（`turns_on` / `turns_off` の件数、`reqs_` `calls_` `serial_` `serialTok_` `parallel_` `prompt_` に `on` / `off` を付けた合計）。どちらも効いたかどうかの判断に使う数字で、**閾値は決めていない。** 仕組みは[節約](savings.md#読み取りをまとめて頼む一文)。

### 自動要約のタイミング（`S` の signal）

`window_pane_<大きさ>`（ペインの目盛りで設定した。例 `window_pane_300k`。モデルの標準に戻した分は `window_pane_auto`）、`window_offer_300k`（提案の「300k にする」で設定した）、`window_typed_pane` / `window_typed_offer`（自動で設定できず、コマンドを入力欄に入れた。本人が Enter を押したかは分からない）。目盛りを動かしただけでは何も残らない。`scripts/ledger-report.sh` の【自動要約のタイミング】に、回数・設定した人の数・大きさ別が出る。

### 提案のはずだった場面

話題が変わった・会話が重い・キャッシュが切れた後の再開、を「提案するはずだった」として数だけ残す（`nudges` の既定の `observe`）。`suggest` にすると[一行の提案](proposals.md#一行の提案)として画面にも出る。

### 節約と引き継ぎメモ

- 節約: `A1`（コマンド出力）、`B1`（サブエージェント）、`B6`（誘導）。数え方は[節約](savings.md)。見込み額 `A1:savedMilliUsd` は「以後 30 ターン読まれる」仮定。
- メモ: `S` の `clear_*`・`compact_*`・`fresh_note_written`・`note_read_*`。[引き継ぎメモ](handoff.md#台帳に残るもの)。

### キャッシュの寿命

`cacheTtlMinutes` が 0 なら自動（API キーは 5 分、サブスクリプションは 60 分）。0〜120 に丸める。これを超えて空くと、キャッシュが切れたとみなす。[Clawd](clawd.md#眠る-キャッシュが切れたとき)と、[提案](proposals.md)の「しばらく空いたため…」が使う。

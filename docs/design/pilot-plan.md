## 1. 目的と、通す基準

Phase 2 は「全員に配る前に、少人数で、介入せずに（または控えめに）動かして、誤検知を潰す」段階。確かめるのは次の 4 つ。

1. 出力ダイジェストが、現実の作業で**やりすぎていないか**（モデルが取りに戻る割合）。
2. 一行の提案が、**邪魔にならず、採用される見込みがあるか**。
3. サブエージェントの格下げ（B1）の**基準値**を取る（まだ格下げはしない。Explore を読み直す割合を、格下げ前のまま測る）。
4. キャッシュが冷えた戻りの**実際の頻度と費用**（仮説の置き換え）。

### Phase 3 に進む条件と、止める線

| 見るもの | 集計の欄 | 進む条件（案） | 直す・止める線 |
|---|---|---|---|
| ダイジェスト: モデルが取りに戻った割合 | 【出力ダイジェスト】 | 25% 以下 | 25% 超で縮める大きさが自動で倍に、50% 超で自動で止まる。その前に原因を見る |
| 施策のエラー | 【評価・不具合】 | 参加者あたり、ほぼ 0 | 同じ施策が 3 回続けて失敗すると、その施策はそのセッションで止まる。起きたら原因を調べる |
| 提案（C1）の採用率 | 【一行の提案】 | 20% 以上の見込み | 20 回以上出して採用 20% 未満・見過ごし 50% 超は、その種類を自動で出さなくなる |
| 提案の見過ごし・金額で見送り | 同上 | 見過ごしが半分を超えない | 超える種類は文面か条件を直す |
| サブエージェント: 読み直した割合と、やり直しの依頼 | 【サブエージェント】 | **基準値が取れたこと**（Explore を 30 回以上） | — （Phase 3 で格下げ後と比べる） |
| 格下げ対象の割合 | 同上 | 起動のうち対象が 10% 以上 | 少なければ許可リストに `general-purpose` を足す検討 |
| 冷えた戻りの頻度・費用、空き時間の分布 | 【キャッシュ】 | 実測が得られたこと | — （C3 と管理者向けの所見の根拠） |
| 👍 / 👎 | 【評価・不具合】 | 👍 が 👎 以上 | 👎 が上回ったら止めて、理由を聞く |

## 2. 参加者と期間

- **5〜10 人、2〜3 週間。**
- 選び方:
  - スタックが偏らない: Vite(React)・Spring Boot または Lambda・Swift が入る。
  - **API 従量課金の人を 2 人以上**（5 分のキャッシュの実測が取れるのは、その人たちだけ）。
  - **ターミナルで対話して使う人**（一行の提案は対話でだけ出る。`claude -p` やクラウドでは記録だけ）。
  - 普段のモデルが Opus / Fable の人を含める（格下げの基準値のため）。
- 2 つのグループに分ける:
  - **提案あり**（半数）: `nudges = suggest`
  - **記録のみ**（半数）: `nudges = observe`（同じ場面を「出すはずだった」と数えるだけ）
- 全員共通: `digest = auto`、`delegation = observe`、`holdoutPercent = 0`、`cacheTtlMinutes = 0`（自動）。
- **提案ありのグループでは、同じことを言う従来のダイアログ（要約する・新しく始める）と、キャッシュ切れの帯の知らせは出さない**（二重に聞かれず、採用の数も混ざらない）。記録のみのグループでは、従来のダイアログがそのまま出るので、そちらでの「要約・`/clear`」も「本人が自分でやった」として数えられる点に注意。

## 3. 設定の渡し方

参加者は `/config` で変えられる。管理者がまとめて渡すなら、settings の `pluginConfigs`（キーはプラグイン名）に書く。後段に置くため、managed の `appendPlugins` で入れる。

```json
{
  "pluginConfigs": {
    "tokenomics": { "options": { "digest": "auto", "delegation": "observe", "nudges": "suggest", "holdoutPercent": 0, "cacheTtlMinutes": 0 } }
  }
}
```

**Linux / WSL の参加者は、`TMPDIR` を本人だけが読めるフォルダに向けておく**（なければ出力ダイジェストは記録だけになる）。

## 4. 参加者に伝えること（そのまま使える説明文）

> **トークン節約 Mod `tokenomics` の試用のお願い**
>
> - 目的: 使うだけで自然にトークンが節約できるかを確かめます。
> - 動くこと: ①成功したコマンドの大きな出力（約 9,000 文字超）を、先頭・失敗の周辺・集計・末尾に縮めてモデルに渡します（失敗したコマンドの出力は縮められません）。全文は一時フォルダに残り、モデルが必要な所だけ読み直せます。②（提案ありのグループ）返信のあとに、一行の提案が出ることがあります。何も自動では入力されません。
> - 記録されること: 効いた回数・トークン数・見込み額・設定。**プロンプト、ファイルの名前やパス、コマンド、会話の内容は、一切記録されません。** 記録は本人の端末（`~/.claude/plugins/store/`）に 14 日分だけ残ります。
> - 送ってもらうもの: 週に 1 回、`/tokenomics export` を実行してください。記録（JSON）がクリップボードにコピーされるので、貼り付けて送ってください。**送る前に中身を見られます**（件数と合計だけです）。画面にはコピーしたことだけが出ます（記録を画面に出すと、会話に入って読み直されるため）。
> - 記録を空にしたいとき: `/tokenomics reset-ledger`（この端末の記録だけが消えます）。参加の前に空にしておくこともできます。
> - 止めたいとき: `/config` で「大きなコマンド出力を縮める」を off、「一行の提案」を off にしてください。プラグインごと無効にしても構いません。
> - 困ったら: `/tokenomics bad`（👎）を押してください。回数だけ記録されます。

## 5. 回収と集計

1. 参加者が週 1 回 `/tokenomics export` を実行する。記録はクリップボードに入る（一時フォルダがあれば `ledger-export.json` にも書く）。貼り付けるかファイルを送ってもらう。
2. 集めたファイルを `scripts/ledger-report.sh export-*.json` に渡す（`jq` が要る）。参加者数・設定の内訳・上の表の指標が出る。
3. 週次で表の判定を見る。
4. 運営者の telemetry collector が使えるなら、いずれ自動化する（管理者への確認事項）。

## 7. 参加者向けの FAQ

- **猫の画像が出ない:** 画像に対応した端末（Ghostty・kitty）だけ。それ以外はブロック文字の猫。tmux の中でも出ない。
- **一時フォルダのコピーは消えますか:** 消す仕組みがありません（API にない）。OS が一時フォルダを掃除します。
- **提案が出ない:** `claude -p` やクラウドでは出ません（対話のターミナルだけ）。金額が小さい場面は、API 課金の人には出しません。同じ種類は 3 ターン以上あけて出します。
- **提案を出したくない:** 「一行の提案」を `observe` か `off` にしてください。
- **不具合かも:** `/tokenomics bad` と、`/tokenomics export` の記録を送ってください。

## 8. 既知の制限

- 提案が出るのは対話だけ。`-p`・クラウドでは記録だけ。
- 金額は入力側の価格だけ（出力の単価は入れていない）。Fable は Opus と同額と仮定している。
- B1（格下げ）は記録だけなので、**この期間の節約は出力ダイジェストだけ**。
- **出力ダイジェストが縮めるのは、成功したコマンド（終了コード 0）の出力だけ。** 失敗したコマンド（落ちたテストなど）の大きな出力は、エンジンが別の形の書き換えを拒むため縮められない（2026-10-11、`claude -p` で確認）。縮められなかった回数は記録に残り（`A1:signal:…:big_error`）、`scripts/ledger-report.sh` に出る。節約の見込みは、その分だけ少なくなる。
- 台帳の日付は本人の時計。
- まだ確かめていない: 対話モードでの読み返し（上の 2）、画面での一行の見え方（上の 1）、VS Code。

# 提案・助言・ペイン

自分で節約術を選ぶ必要はない。**節約が効く場面で、提案が出る**。受け入れると、そのまま実行される。

← [README](../README.md)

## 提案

```
┌─ 提案 ──────────────────────────────────────────────────┐
│ <[o_o]> 会話が重くなってきました                          │
│   長い会話は、返信のたびに全体を読み直すぶん消費が増えます。 │
│   要約すると、この先が軽くなります。                        │
│   失われやすい詳細をメモに残してから要約します。            │
│   [ 要約する ]  [ あとで ]  [ もう出さない ]              │
└──────────────────────────────────────────────────────────┘
```

### 出方

- **出る場所:** まずダイアログ（ペイン）。ただし、Mod が自発的に出すペインは**端末が 144 桁以上ないと表示されない**ので、狭い端末では**同じ内容を、プロンプト上の枠付きカード**として出す。どちらも「受け入れる／あとで／もう出さない」。画面の真ん中に重ねる表示は、API にない。
- **キーボードは奪わない:** 返信の直後は入力を始める頃なので、ダイアログはフォーカスを要求しない（要求すると、打ちかけの文字が取られるおそれがある）。ボタンはクリックで押す。キーボードなら `ctrl+x` `tab` で枠に移る。入力欄が空のとき Esc で閉じられる（= あとで）。実機で問題がなければ `register.tsx` の `DIALOG_TAKES_KEYS` を `true` にすると、フォーカスを要求する。
- **出るタイミング:** 返信が終わったあと（返信中は出さない）。計測が更新されたとき（`session.measure`）や、作業フォルダが変わった直後にも出る。次のプロンプトを送ると下げる（`/` で始まるコマンドでは下げない）。状況が変わって合わなくなった提案は、自動で下げる。古い提案を押すと「状況が変わったので見送りました」と出る。
- **頻度は控えめ:** 同じ種類は 1 セッションに 1 回まで（「要約する」だけ、重い状態が終わるたびにまた出す）。同時に出るのは 1 枚。
- **「もう出さない」は覚える**（次回以降も）。`/tokenomics settings` の「止めている提案」から再開できる。

### 提案の種類

受け入れた節約は、すべて**そのセッションの間だけ**有効。例外は設定を書き換える 3 つ（自動要約・自動要約のタイミング・プロンプト提案。設定に保存される）と、モデル（終了時に元へ戻す）。`/tokenomics settings` の「いま効いている節約」からいつでもやめられる。

| 提案 | 出る場面 | 受け入れると |
|---|---|---|
| 要約する | 会話が重くなったとき（20 万 tok を満杯として 70%、つまり約 14 万 tok。90%、約 18 万 tok でさらに強く） | 失われやすい詳細（依頼・触ったファイル・実行したコマンド・最後の回答）を一時フォルダへメモに残してから `/compact`。以降の要約（手動・自動）でも、メモを残す（`handoffNote` がオンなら、提案を受け入れなくてもメモは残る） |
| 新しく始める | コミット／プルリクエストの作成・マージ／作業フォルダの変更のあと（失敗したコマンドは除く）。会話そのものが 20k tok 以上のとき（ウィンドウは最初から 20k 以上を占めているので、下地を除いて数える） | 入力欄に `/clear` を入れるだけ。Enter が確認になる。書きかけの入力は上書きしない |
| 自動要約をオンにする | 自動要約がオフで、会話が重いとき。`/config` の行が管理者などに固定されていないとき | 設定をオンに（**設定に保存される**）。メモも残すようにする |
| 自動要約のタイミングを 300k にする | 自動要約が始まる大きさがエンジンの標準のまま（100 万トークンの窓なら約 96.7 万 tok）で、その大きさが 40 万 tok 以上、かつ会話が一度でも約 14 万 tok を超えたとき（要約して軽くなったあとでも、まだ出る。`/clear` で数え直し）。自分や管理者が決めた大きさのときは出さない | `/autocompact 300k` を**実行する**（受け入れるボタンが確認）。実行後にエンジンが報告する大きさを読み直して、変わったことを確かめてから「できた」と言う。実行できない版・変わらなかったときは、入力欄に `/autocompact 300k` を入れて Enter を待つ（書きかけの入力は上書きしない）。約 26.7 万 tok で自動要約が始まる（設定した大きさの約 3.3 万 tok 手前）。**モデルごとに保存される**。戻すには `/autocompact auto`（設定ペインの「標準に戻す」も同じ）。設定ペインから、100k〜1M の好きな大きさに変えられる |
| 軽いモデルへ | 会話そのものが小さい（20k tok 以下。下地は除く）うちに、簡単な作業が続く／上限が 70% を超えたとき。切り替えで読み直す全体の大きさも文面に出す。すでに切り替え中、`/config` に軽いモデルがない、移し先に会話が収まらない（窓 20 万以下のモデルへ 16 万 tok 超）ときは出さない | Sonnet（Sonnet なら Haiku）へ切り替える。`/model` と同じ操作なので次回にも保存されてしまう。そのため元のモデルを記録し、**終了時に自動で戻す**（異常終了しても次の起動で戻す。途中でご自身が別のモデルにしていたら触らない） |
| 考える深さを下げる | 簡単な作業（短い依頼・ツール 1 回以内・画面に出る返事が 600 字以内）が 3 回続き、effort が高いとき。出力トークンでなく画面の返事で判定する（考えた分も出力に数えられ、5 系では考えるのをやめさせられないため） | このセッションだけ effort を「ふつう」にする。下げるだけで、上げない。サブエージェントには触れない。公式ドキュメントでは、現行のモデルなら変えてもキャッシュは保たれるとされている |
| プロンプト提案をオフにする | 5 ターン以上続いて、オンのとき。`/config` の行が固定されていないとき | 返信のたびに走る「次の入力の候補」の小さなリクエストを止める（**設定に保存される**） |

受け入れて「考える深さ」を下げている間だけ、帯に `節約中: effort ふつう` と出る。ほかの節約（モデル・メモ）は帯には出ず、設定ペインの「いま効いている節約」に並ぶ。

### 提案に入れなかったもの

- 「返信を短くする」: 公式に裏付けがなく、効果も不確か。
- 使っていない MCP サーバーの停止: この Mod から操作する API がない。「重いもの」のヒントで `/mcp` を案内するだけ。

## 助言（押すものがない知らせ）

提案とは別に、帯の下に 1 行、押すものがない知らせが出ることがある。「あとで」で消すと、状況が解消するまで再表示されない。

| 知らせ | きっかけ |
|---|---|
| 5 時間・週次・利用額の上限が近い | 上限 80% / 95%（定額プランのみ） |
| 〇〇の出力が大きめでした | 1 回のツール結果が約 10k トークン超（範囲を絞る方法つき） |
| 前回から約 N 分あきました。最初の返信で会話全体（約 N tok）を読み直します | 時間をおいて再開（`--resume` / `--continue` / フォーク）したとき、エンジンの情報でキャッシュが切れていそうで、会話が 20k tok 以上のとき。API 課金なら読み直しの金額、定額プランなら「上限を多く使います」。要約から始めても最初の 1 回は同じ読み直しになるので、避けられるのは `/clear` だけ、と書く。最初のプロンプトを送ると消える。（Pro/Max では、エンジン自身も長い休みのあとに要約からの再開を勧める） |
| しばらく空いたため、会話の読み直しが発生しました（約 N tok） | 約 5 分以上空けて再開し、その返信が、停止前の文脈の半分以上を実際にキャッシュへ書き直したとき（コンテキスト 20k 超）。推測では出さず、使用量で確かめてから出す |

モデルを自分で切り替えるときも、キャッシュが温かい大きな会話なら確認が出る（API 課金なら読み直しの金額、定額プランなら「上限を多く使います」）。

## 一行の提案

`nudges` を `suggest` にすると、返信が終わったあとに**一行**の提案を出す。返信そのものは変えず、プロンプトへの入力もしない（`/clear` を打つのは本人）。

- **出る場所:** Clawd（`hud` がオン）のときは、帯のカードの中。いつも Clawd の一言（「のんびり歩いています」など）が出ている場所に、一行が入れ替わって出る。`hud` がオフのときは、帯が出ないので、返信のあとに別の行として出す。その行頭の `tokenomics:` はエンジンが付ける接頭辞で、ほかのプラグインを入れていると名前が並ぶことがある（実機で見た。なぜ並ぶかは未確認）。
- **いつまで:** 次にプロンプトを送る（`/` で始まるコマンドは除く）、`/clear`、要約（`/compact` やペインの「要約する」）、新しいセッションのどれかで消える。
- **出ない間:** AI が作業している間と、提案のカード（要約する・新しく始める）が開いている間は隠れて、終わったあとにまた出る。主会話で正常に終わった返信のあとだけ出る（中断・エラー・サブエージェントでは出ない）。
- **狭い・長いとき:** 一行がカードの幅で折り返すと、その分カードが高くなる。表示できる高さがなければ、1 行の帯に切り替えて、その下に一行を出す。

| 場面 | 帯のカードの中（短い） | `hud` オフ・別の行（長い） |
|---|---|---|
| 会話が重い | 重くなってきました（毎回 約120k tok を読み直し）。区切りで /compact を。 | 会話が重くなってきました（返信のたびに約 120k tok を読み直します）。区切りのよいところで /compact を。 |
| 会話がかなり重い（`strong`） | かなり重くなっています（毎回 約Ntok を読み直し）。/compact か、別件なら /clear を。 | 会話がかなり重くなっています（返信のたびに約 N tok を読み直します）。/compact で要約するか、別件なら /clear で新しく始めると軽くなります。 |
| 別件のようだ | 別件のようです。/clear で約80k tok の読み直しがなくなります（今の回答は消えます）。 | 別件のようです。/clear で新しく始めると、以降の読み直し（約 80k tok）がなくなります（今の回答は消えますが、要点は /clear のときに自動でメモに残ります）。（`handoffNote` がオフ、または一時フォルダが自分専用でないときは「…今の回答も消えるので、残したい内容は先に /tokenomics handoff でメモを」） |
| 空いてキャッシュが切れた | 空いたため会話全体（約81k tok）を読み直しました（約 $0.41）。別件なら /clear が一番軽いです。 | しばらく空いたため、会話全体（約 81k tok）を読み直しました（約 $0.41）。続きが別件なら、/clear が一番軽くなります。 |

- **控えめにするルール:** 1 回の返信に 1 つまで。前の提案から 3 ターン以上あける。API 課金では、避けられる額が 5 セント未満のものは出さない（定額プランでは、トークン量で判断）。「キャッシュが切れた」は、その返信が実際に会話全体を書き直したときだけ。複数の候補があるときの優先順位は、かなり重い > キャッシュが切れた > 別件 > 重い。候補は 2 ターンで古くなる。
- **出る相手:** 対話のターミナルで使っている人だけ。`claude -p`・クラウドでは記録だけ。効果を測る側の人にも出さない。
- **従来の提案との関係:** 「会話が重い」「別件」の一行を `suggest` にしている間は、同じことを言う[提案](#提案)のダイアログ（要約する・新しく始める）を出さない。「キャッシュが切れた」を `suggest` にしている間は、帯の「しばらく空いたため…」の知らせも出さない。二重に聞かれないため。一行の提案が自動で引っ込んだ（採用されない）場合は、従来のダイアログに戻る。
- **採用されなければ自分で引っ込める:** 提案後 3 ターン以内に、手で打った `/compact`・ペインの「要約する」ボタン・`/clear` をしたら「採用」、しなければ「見過ごし」と数える（自動要約は採用に数えない）。種類ごとに直近 14 日を見て、20 回以上出して採用が 2 割未満、見過ごしが半分超の種類は、出さなくなる。
- **見え方の確認:** `/tokenomics nudge-test` を実行して、短い質問を送ると、返信のあとに見本の一行が 1 回出る（設定に関係なく）。

## ペイン

`[ 詳しく分析 ]`（または `/tokenomics`）が**分析ペイン**を、`[ 設定 ]`（または `/tokenomics settings`）が**設定ペイン**を出す。ペインは同時には一つだけで、一方を押すともう一方は閉じる。どちらの上にも、もう一方へ行くボタンがある。ペインが置けない狭い端末では、同じものを文字で返す（分析は状態と「今やること」だけ。設定は現在の行と `/autocompact 300k` の案内だけ）。

| ペイン | 中身 |
|---|---|
| 分析 | 今やること（受け入れ待ちの提案と助言）・いまの状態・今日の節約・直近のリクエストのグラフ・重いもの・節約のコツ（ペインの高さが 40 行以上のときだけ）。[数字の意味](numbers.md) |
| 設定 | 自動要約のタイミング（下）・いま効いている節約（それぞれ止められる）・Clawd のようす（帯に描画中のときだけ。動きを減らす設定でないとき）・止めている提案（1 件以上あるときだけ。再開できる） |

要約まわりの数字は、提案を受け入れたときも、手で `/compact` したときも、自動で要約されたときも、同じように更新される。

## 自動要約のタイミング（スライダー）

設定ペインの先頭にある、自動要約が始まる大きさを選ぶ部品（モデルの窓が 40 万 tok 以上のとき）。選ぶのは**窓（モデルが受け付ける上限。1M など）ではなく、自動要約が始まるタイミング**（`/autocompact` の値。エンジンは auto-compact window と呼ぶが、窓そのものは変わらない）。費用を決めるのはこのタイミングだけで、窓が大きくても、使わなければ料金は変わらない。要約を早めにするなら、窓は小さくても足りる。大きな窓が役に立つのは、要約を遅らせたい作業のときと、1 回のターンで会話が急に増えたときの余白だけ。

エンジンに「スライダー」の部品はないので、100k〜1M の目盛りをボタンで並べる（目盛りはモデルの窓の大きさまで。13 個になるのは 1M の窓だけ）。`●` が選んだ大きさ、`★` が 300k（おすすめ）、`◆` がいまの設定（端末のみ）。目盛りを押すか、「◀ 小さく」「大きく ▶」で動かす。**ペインを開くたびに、いまの設定ではなく 300k に合わせる。** 動かした位置は、押して設定したあとはその大きさのまま、開き直すと 300k に戻る。

選ぶと、その下に次が出る。

- 費用の目安（サブスクでは使用量）… 標準（モデルの窓、1M なら約 96.7 万 tok で要約）に比べて何 % 少ないか、いまの設定に比べて何 % 少ない（多い）か。
- 要約が始まる大きさ（設定した大きさの約 3.3 万 tok 手前。エンジンが報告する値から読む）と、要約の回数（長く続く会話 1 本あたり）。
- 300k では、なぜおすすめかの一行。
- 「300k にする（おすすめ）」（主ボタン。選んだ位置がいまの設定のときは出ない）と、「標準に戻す」（`/autocompact auto`。設定が標準より小さいときだけ）。自動要約がオフのときは、その旨だけ出してボタンは出さない。環境変数・管理者が決めている場合は、反映されないことがある旨を添える。

ボタンを押すと `/autocompact` を**実行**し（押すこと自体が確認。モデルごとに保存される）、エンジンが報告する大きさが変わったことを確かめて知らせる。実行できない版・変わらなかったときは、コマンドを入力欄に入れて Enter を待つ。

### 数字の根拠

この PC で最も大きかった 5 つのセッション（約 3,000 リクエスト、実費 約 $240）を、各設定で再計算した目安（5% 刻みで丸めている）。設定ごとに、リクエストのたびに会話全体をキャッシュ読みの単価で読み、増えた分を書き込みの単価で書く。要約のたびに、会話を 1 回読み、40k の出だしを書き直し、要約の出力（1.2 万 tok、入力の 5 倍の単価）を払い、ファイルの読み直し（6k tok）を足してある。**入れていない**のは、要約で失う細部。

| 設定 | 標準（1M の窓）に比べた削減 |
|---|---|
| 100k | 約 25%（要約が多すぎて、要約自体の費用が積み上がる。長いセッション 1 本で約 46 回） |
| 150k〜250k | 約 50% |
| 300k | 約 45% |
| 400k | 約 40% |
| 500k | 約 35% |
| 600k | 約 20% |
| 800k | 約 5% |

300k を勧めるのは、最大の削減（約 50%）に近いまま、要約の回数が 200k の約半分（約 6 回と約 11 回）で、細部を失う機会が少ないため。会話が選んだ大きさまで育たないうちは、どの設定でも費用は変わらない。窓が 40 万 tok 未満のモデルでは、この部品は出さない（標準でも十分早く要約される）。

## 確かめたこと・確かめていないこと

| 項目 | 状態 |
|---|---|
| 設定ペインの「300k にする」 | 実機で確かめた（2026-10-12）。組み込みの `/autocompact 300k` が実行され、設定が `~/.claude/settings.json` の `modelSettings.<モデル>.autoCompactWindow` に保存され、トーストが出て、ペインの「いまの設定」が 300k になった |
| コマンドを入力欄に入れる側（実行できない版・変わらなかったとき）、「標準に戻す」 | テストだけ。実機は**未確認** |
| 144 桁未満でダイアログのペインが置かれないこと、キーボードでの移動 | コードからは確かめられない。実機での確認が要る |
